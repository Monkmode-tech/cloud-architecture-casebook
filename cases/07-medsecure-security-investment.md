# Case 7: A security program a CFO can approve

> **Client:** MedSecure Commerce (fictional, CLCS 645, Unit 6): healthcare product orders, customer PII,
> payments and analytics
> **My role:** security architect
> **Decision in one line:** cloud-native controls first, spend scaled by data class, and an ROI
> stated with its assumptions instead of a best case.

## The situation

The company had a flat network, manually managed IAM, inconsistent encryption and little log
correlation. It needs a security architecture that is strong *and* sustainable: affordable,
automated, and not dependent on heroics.

## Defense in depth on AWS

| Layer | Controls | Services |
|---|---|---|
| Identity | Least privilege, MFA, short-lived credentials, break-glass, quarterly reviews | Organizations + SCPs, IAM Identity Center, Access Analyzer |
| Network | Public / app / data / security subnets; no internet path to databases; private service access | VPC, security groups, NACLs, Network Firewall, PrivateLink |
| Data | Encrypt everything; a key per data class; rotated secrets | KMS, ACM, Secrets Manager, SSE-KMS |
| Application | Injection, bots, DDoS, image vulnerabilities | WAF, Shield Advanced, API Gateway, ECR scanning, Inspector |
| Detect & respond | Central logs, automated containment, immutable evidence | CloudTrail, GuardDuty, Security Hub, EventBridge, S3 Object Lock |
| Recover | Multi-AZ, immutable backups, tested restores | RDS Multi-AZ, AWS Backup, versioning, Route 53 failover |

Organized by **NIST CSF 2.0**: Govern, Identify, Protect, Detect, Respond, Recover.

## Threats and the metric that proves each control works

| Threat | Risk | Key controls | Metric |
|---|---|---|---|
| Credential compromise | Critical | MFA, Identity Center, GuardDuty | MFA coverage ≥ 99% |
| Web/API attacks | Critical | WAF managed rules, throttling | Blocked requests, API error rate |
| Misconfiguration | Critical | Security Hub, Config, SCPs, IaC scanning | Compliance score ≥ 90% |
| Ransomware / deletion | High | Object Lock, AWS Backup, KMS | Backup success ≥ 99%; quarterly restore test |
| Container vulnerabilities | High | ECR scanning, Inspector, CI gates | Criticals fixed ≤ 7 days |
| Insider misuse | High | Separation of duties, CloudTrail, JIT admin | 100% of privileged sessions logged |

Operational KPIs: mean time to detect ≤ 15 min, contain a critical incident ≤ 60 min, zero public buckets.

## Is it worth $490k over three years?

The coursework estimated **798% ROI** by assuming the program prevents one average breach
($4.4M) for certain. A board will ask "what if no breach was coming anyway?" A better model
treats a breach as a probability: annualized loss expectancy (ALE = annual rate × loss per breach).
It reports the condition under which the investment pays off. Generated by
[`tools/security_roi.py`](../tools/security_roi.py) from
[`models/medsecure-rosi.json`](../models/medsecure-rosi.json):

### What the numbers say

- With a 15% yearly chance of a major breach and controls that halve it, the program returns
  **about 2.4× its cost**. That is still a strong case, but a third of the original claim.
- **It pays for itself if the yearly chance of a major breach is above ~4–5%.** For a company holding
  healthcare PII and payment data, few security leaders would argue the risk is lower. Stated
  this way, the decision rests on one debatable number instead of a hidden assumption.
- Bold cells are where the program loses money: rare breaches *and* weak controls. That's the
  argument for measuring control effectiveness (the metrics table above) rather than assuming it.

## Built, not just designed

[**aws-security-guardrails-detection**](https://github.com/Monkmode-tech/aws-security-guardrails-detection)
implements the detect-and-respond layer: CloudTrail with 14 CIS detections, GuardDuty, Security
Hub (FSBP + CIS), Config rules, auto-remediation Lambdas, ABAC for PHI, and attack simulations
that measure time-to-remediate.

## What I'd do differently now

- **Present ROI as expected loss with a break-even point**, as above, never as "one avoided breach".
- **Use the healthcare breach cost ($7.42M, IBM 2025), not the global average ($4.44M)** when the
  data is healthcare. The industry matters more than the precision.
- **Fund Shield Advanced only where the numbers justify it.** At ~$3,000/month it is a large part of
  the budget. CloudFront + WAF rate-based rules cover most DDoS risk for a company this size.
